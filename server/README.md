# Сервер игры

Игра живёт на сервере **45.67.216.36** отдельно от всего остального.
Ничего общего с chesscoin, jobtop и Claudia у неё нет: своя папка,
свой контейнер, своя сеть, свой порт, свой домен, свой сертификат.
Остановка или поломка игры не задевает соседние проекты, и наоборот.

**Адрес игры:** https://magazin.45-67-216-36.sslip.io/
**Приложение:** https://magazin.45-67-216-36.sslip.io/magazin.apk

Домен `*.sslip.io` — это не регистрация домена, а служба, которая
превращает адрес вида `magazin.45-67-216-36.sslip.io` в IP `45.67.216.36`.
Нужен он ради HTTPS: без защищённого соединения браузер не разрешает
офлайн-кэш, а значит и авто-обновление. Как только появится нормальное
имя вроде `magazin.ru`, его достаточно направить на этот же IP
и выпустить сертификат — всё остальное менять не придётся.

## Что где лежит

```
/opt/magazin/
├── www -> releases/ГГГГММДД-ЧЧММСС   ссылка на текущую версию
├── releases/                          пять последних версий, для отката
├── apk/magazin.apk                    собранное приложение
├── android/                           исходники оболочки + build-apk.sh
├── android-sdk/                       Android SDK (437 МБ), только для игры
├── docker-compose.yml                 контейнер magazin-web
├── nginx/site.conf                    nginx внутри контейнера
├── deploy.sh                          выкладка новой версии
├── autopull.sh                        крон: следит за GitHub
└── releases/                          старые версии
```

На хосте:
- `/etc/nginx/sites-available/magazin` — отдельный файл, отдельное имя
  домена, проксирует на `127.0.0.1:8091`. Конфиги других сайтов не тронуты.
- Сертификат Let's Encrypt, продлевается сам.
- Крон `*/2 * * * * /opt/magazin/autopull.sh`.

## Как выложить новую версию

Обычно — ничего делать не надо: `git push` в `main`, и через пару
минут крон сам заберёт код и выложит. Ещё через пару минут игра
на телефонах перейдёт на новую сборку.

Вручную:

```bash
/opt/magazin/deploy.sh              # забрать с GitHub и выложить
/opt/magazin/deploy.sh rollback     # вернуться на предыдущую версию
```

Выкладка устроена так, что сломанная версия до игроков не доедет:
сначала всё раскладывается в новую папку, проверяется комплектность,
и только потом одним движением переставляется ссылка `www`. Если
проверка не прошла — на сервере остаётся прежняя рабочая игра.

## Как обновляется игра на телефоне

1. Сервер отдаёт `version.json` с номером сборки и запрещает его кэшировать.
2. Игра спрашивает этот файл при запуске, при возврате на вкладку
   и раз в три минуты.
3. Номер изменился — service worker скачивает новые файлы в фоне.
4. Если игрок в меню, страница обновляется молча. Если идёт игра —
   внизу появляется полоска «ВЫШЛА НОВАЯ ВЕРСИЯ · ОБНОВИТЬ»,
   чтобы прохождение не оборвалось на середине.
5. Старый кэш стирается целиком, поэтому смеси старых и новых
   файлов не бывает.

Аварийный выход, если что-то всё же застряло: открыть адрес
с `?nosw=1` — снимет кэш и service worker.

## Как пересобрать приложение

```bash
/opt/magazin/android/build-apk.sh
```

Нужно это редко: приложение — тонкая оболочка вокруг WebView,
сама игра приезжает с сервера. Пересборка требуется, только если
менялся `MainActivity.java`, иконка или адрес игры.

⚠️ `android/keystore/magazin.keystore` терять нельзя. Телефон принимает
обновление приложения, только если новый apk подписан тем же ключом.
Файл намеренно не лежит в git — храните копию отдельно.
