# Инструкция для Claude Code

Проект: браузерная игра «Заброшенный магазин», две части.
Задача этого этапа: выложить игру на GitHub Pages и подключить
профили с прогрессом через Supabase.

Автор игры — Абдул, 10 лет. Пишет вместе с Claude.
Заказчик — Кенан. Все обсуждения ведутся в чате, сюда приходят готовые задания.

---

## Что уже есть в этой папке

```
index.html                      главная: выбор части + профиль
part1.html                      игра, часть I  (самодостаточный файл)
part2.html                      игра, часть II (самодостаточный файл)
js/config.js                    ключи Supabase — ЗАПОЛНИТЬ
js/profile.js                   профиль, вход, сохранение прогресса
supabase/schema.sql             схема базы — ВЫПОЛНИТЬ в SQL Editor
.github/workflows/keepalive.yml антисон для бесплатного тарифа
```

`part1.html` и `part2.html` — цельные файлы без зависимостей,
кроме three.js с CDN. Их **не нужно** разбирать на модули.

## ЭТАП 1. Репозиторий и Pages

1. Создать **публичный** репозиторий, например `abandoned-store`.
2. Залить содержимое этой папки в корень ветки `main`.
3. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
4. Дождаться сборки. Ссылка будет вида
   `https://<логин>.github.io/abandoned-store/`

**Проверка этапа:** ссылка открывается с телефона, обе части
запускаются, в блоке «ПРОФИЛЬ» написано «Офлайн: прогресс
сохраняется только здесь». Это нормально — сервера ещё нет.

---

## ЭТАП 2. Supabase

1. Создать проект (регион ближе к Азербайджану — `eu-central`).
2. SQL Editor → выполнить целиком `supabase/schema.sql`.
3. Authentication → Providers:
   - **Email** включить;
   - **Confirm email** ВЫКЛЮЧИТЬ (почта у нас ненастоящая, подтверждать нечего);
   - **Anonymous sign-ins** ВКЛЮЧИТЬ — на этом держится вход без регистрации.
4. Project Settings → API: скопировать `Project URL` и `anon public` ключ
   в `js/config.js`.
5. Закоммитить и запушить.

Оба значения публичные, их место в открытом репозитории.
Безопасность обеспечивают политики RLS из `schema.sql`,
а не секретность ключа. Ключ `service_role` в репозиторий
не класть **никогда**.

**Проверка этапа:** открыть ссылку, в профиле должно появиться
имя вида `Игрок-A1B2` и текст «Прогресс в облаке».
В Supabase → Table Editor → `profiles` появилась строка.

## ЭТАП 3. Антисон

Бесплатный проект засыпает после 7 суток без запросов.

1. Settings → Secrets and variables → Actions → New repository secret:
   - `SUPABASE_URL` — тот же Project URL
   - `SUPABASE_ANON_KEY` — тот же anon ключ
2. Actions → keepalive → Run workflow (проверить руками).

Дальше он ходит сам раз в трое суток.

**Проверка этапа:** в логе запуска строка `Ответ базы: 200`.

## ЭТАП 4. Подключить сохранения к самим играм

Сейчас обе игры хранят прогресс в своей памяти и теряют его
при перезагрузке. Нужно связать их с `Profile`.

В `part2.html` есть готовый объект `SAVE` и функции
`saveAt(id)` / `loadSave()`. Требуется:

1. В `<head>` обеих игр добавить перед основным скриптом:
   ```html
   <script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
   <script src="js/config.js"></script>
   <script src="js/profile.js"></script>
   ```
2. При запуске игры вызвать `Profile.init(...)`.
3. В `saveAt(id)` после заполнения `SAVE` добавить:
   ```js
   Profile.save(2, {id:SAVE.id, name:SAVE.name, inv:SAVE.inv});
   ```
4. При старте игры подтянуть облачное сохранение:
   ```js
   Profile.load(2, function(data){
     if(data){ SAVE.has=true; SAVE.id=data.id; SAVE.name=data.name; SAVE.inv=data.inv; }
     menuOpen();
   });
   ```
5. Для `part1.html` — то же самое с номером части `1`.
   В первой части точек сохранения пока нет, их надо будет
   добавить отдельным заданием.

**Проверка этапа:** пройти до первого склада, закрыть вкладку,
открыть заново — в меню кнопка «ПРОДОЛЖИТЬ» активна и ведёт
в нужное место. Затем открыть ссылку на другом устройстве,
войти по нику — прогресс тот же.

## Чего делать НЕ надо

- Не разбирать `part1.html` и `part2.html` на модули: они рабочие,
  и любая перестройка сейчас сломает больше, чем починит.
- Не менять игровую логику и баланс без задания из чата.
- Не переименовывать `saveAt`, `loadSave`, `SAVE`, `PHASE` —
  на эти имена завязан весь код.
- Не класть в репозиторий `service_role` ключ.
